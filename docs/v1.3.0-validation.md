# v1.3.0 B站合集差集与幂等批量验证

> 日期：2026-08-24  
> 范围：内容提交幂等、B站合集冻结、批次选择与状态、版本化 Skill bundle

## 功能门禁

发布候选必须证明：

1. 同一 BVID 即使跟踪参数不同，也只产生一个非失败内容 Job；
2. 已失败任务不阻止重新提交；
3. v1.2.5 旧 manifest 没有 `submission_id` 时仍可按 BVID 复用；
4. 合集列表和成员分页会冻结并去重；
5. 合集接口临时失败时仍保留旧的作者清单和按数量下载能力，并把合集状态标记为不可用；
6. `missing` 排除已有非失败任务，全部已存在时以 0 个子任务完成；
7. `collection` 只使用父任务冻结的成员关系；
8. `explicit` 拒绝格式错误、重复或不属于冻结作者清单的 BVID；
9. 旧的按最新数量下载接口保持兼容；
10. 父任务状态返回紧凑的选择、合集和覆盖摘要；
11. 已发布版本包不可变，v1.3.0 包与根 Skill 文件逐字节一致。

每个完成任务必须精确具有 `video`、`transcript_txt`、`transcript_srt` 和 `transcript_json` 四种角色，且实际文件存在、字节数和 SHA-256 与 manifest 一致。

## 发布后门禁

合并后从公开 `skill-releases/v1.3.0/wechat-archive` 路径安装到隔离 HOME，并验证：

1. Skill 与 worker 版本为 `1.3.0`；
2. 六个版本包文件完整且与根文件一致；
3. 已固定的透明核心版本和 SHA-256 未变化；
4. `self-check` 返回 `ok: true`；
5. 对隔离归档连续提交同一 BVID 两次，第二次返回同一 Job 和 `reused: true`；
6. 对真实已完成归档执行 `missing` 选择时不创建重复内容任务；
7. 本地后端状态接口仍返回 200，未授权敏感接口仍返回 403。

全部门禁通过后才创建 GitHub Release。
