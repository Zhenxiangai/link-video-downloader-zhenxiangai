## 暴露的问题

旧版作者批量只接受“从最新开始的数量”。合集与全量清单是两套视图，合集并不覆盖全部作品；如果先下载合集、再下载作者全部历史，旧版会为相同 BVID 创建第二个任务。父任务也无法表达“一个合集”“明确 BVID”或“只补缺失项”。

这不是下载器失效，而是提交身份和批次选择能力不足：

1. `submit_content` 每次先创建新 Job，未在共享入口复用已有非失败内容；
2. B站作者盘点只冻结视频列表，没有冻结合集成员关系；
3. `creator_batch.selection` 只有 `limit`，不能表达其他明确范围；
4. 状态接口虽然已有父任务计数，但没有返回选择、合集和覆盖摘要。

## v1.3.0 决策

- 在共享内容提交入口按平台内容标识加文件锁和幂等复用；失败任务仍允许重新提交。
- 保持原有两步确认契约和 `download-creator-plan` 数量接口不变。
- B站盘点额外冻结合集及成员 BVID，并为每个视频记录所属合集。
- 新增 `download-creator-selection`，支持 `all`、`missing`、`collection` 和 `explicit`。
- 父任务状态只返回紧凑选择和合集摘要，不回显整份 BVID 清单。
- 不增加数据库、队列服务或并发 worker；当前本地规模使用受锁保护的线性 manifest 扫描。

## 边界

“全部”和“缺失”均基于盘点时当前账号可见且可访问的冻结清单。已删除、私密、无权付费内容和被风控隐藏的内容不在承诺范围。合集接口和网页结构仍可能随平台更新而变化。
