# v1.2.5 公众号文章兼容与归档验证

> 日期：2026-08-20
> 对象：匿名公开微信公众号
> 范围：包装层文章解析、媒体 URL 归一化、版本化 Skill bundle
> 隐私：不包含公众号名称、文章标题、原文链接、个人路径、Cookie 或会话字段值

## 1. 本次修复

`v1.2.5` 继续固定已发布并复验的核心 `v260810-zhenxiangai.3`，仅修复包装层两项实战缺陷：

1. 纯图片文章不得再因正文少于 20 字被误判为无正文；
2. 历史页面中的 `http://mmbiz.qpic.cn` 图片可在严格条件下升级为 HTTPS。

纯图片文章必须同时满足：

- 验证标记数为 0；
- 标题存在且不是通用微信标题；
- 页面存在真实 `js_content` 容器；
- 至少发现一张图片；
- 至少成功校验并归档一张图片。

HTTP 图片升级会先按 ASCII 小写规范化 authority，再仅允许结果精确等于 `mmbiz.qpic.cn` 或 `mmbiz.qpic.cn:80`。任意其他 HTTP、空 userinfo、空端口、尾点主机、替代端口写法、主机后缀欺骗和畸形 authority 均继续拒绝或隔离为单张媒体失败。

## 4. 自动化门禁

发布候选必须通过：

```bash
python3 -m compileall -q scripts tests
python3 -m unittest discover -s tests
git diff --cached --check origin/main
```

回归覆盖包括：

- 精确微信图片主机 HTTP→HTTPS；
- 恶意后缀、账号信息和非默认端口不升级；
- 畸形媒体端口只隔离单张媒体；
- 有效纯图片文章成功；
- 通用标题、无标题或包含验证标记的图片页拒绝；
- 纯图片文章没有任何成功媒体时拒绝完成；
- 当前 `v1.2.5` bundle 与根文件逐字节一致；
- 已发布 `v1.2.4` 六个 bundle 文件由固定 SHA-256 永久保护。

## 5. 发布后门禁

合并与发布后仍须从公开 GitHub `skill-releases/v1.2.5/wechat-archive` 路径安装到隔离目录，并验证：

1. Skill 版本为 `1.2.5`；
2. 六个 bundle 文件完整；
3. bootstrap 固定的核心下载与校验保持不变；
4. 自检通过；
5. 本地后端状态接口返回 200；
6. 未授权敏感接口仍返回 403。

完成该门禁后，才能把 GitHub Release 标记为发布完成。
